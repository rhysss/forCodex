一、需求分析

1.1 背景

平台需要一种可控的风险处置手段：当个别用户的盈利仓位给平台带来较大风险敞口时，由运营在中台对该仓位进行手动减仓。对用户侧，这笔减仓以行业通行的「ADL 自动减仓」形式呈现。

本需求包含两部分：

  • 中台：在「当前持仓列表」上，运营可对满足条件的仓位输入数量执行 ADL 减仓。
  • 用户端（App / Web）：被减部分仅在历史委托中展示 ADL 数据和标签，其余历史不新增 ADL 数据或标签。

1.2 用户分析

角色诉求本期满足方式
运营 / 风控（使用方）按需减仓并追溯各人员操作张数输入与执行预览；减仓数量下方展示所有人员的历史操作日志
被减仓用户（影响方）了解减仓成交和实际费用仅历史委托展示 ADL 数据、标签及说明；手续费按实际适用费率收取

2.3 术语解释

术语说明
ADL（自动减仓）对用户展示的名称。本需求中实际由运营在中台手动发起。
ADL 指示灯（呼吸灯）/ ADL 档位平台现有的 1–5 格指示，表示仓位被 ADL 的排队位置，格数越多越靠前。灯数沿用现有计算逻辑；中台删除 ADL 档位展示，资格判断仍沿用现有逻辑。
张 / 币 / USDT数量的三种单位。币数量 = 张数 × 合约面值（如 BTCUSDT 1 张 = 0.0001 BTC）；USDT 数量 = 币数量 × 当前标记价格。
持仓量 / 可平量可平量 = 持仓量 − 被平仓挂单占用的数量。ADL 的上限按持仓量计算。
平仓类挂单该仓位上的止盈止损单、只减仓委托等平仓方向的未成交委托。
标记价格平台用于计算未实现盈亏和强平的参考价格。ADL 按执行那一刻的标记价格成交。
平台账户承接 ADL 所产生盈亏的平台自有账户。

2.4 计算口径（沿用《账户字段公式》）

本需求不新增计算口径，全部沿用现有《账户字段公式》，ADL 视同一次按标记价格成交、按实际适用费率收取手续费的平仓。

字段公式使用位置
单个仓位未实现盈亏仓位方向 ×（标记价格 − 开仓均价）× 面值 × 张数（多 +1 / 空 −1）列表、弹窗、用户端持仓
平仓盈亏（本次减仓预估盈亏）仓位方向 ×（平仓均价 − 开仓均价）× 面值 × |张数|；ADL 平仓均价 = 执行时标记价格；本次净盈亏扣除实收手续费弹窗「本次减仓预估盈亏」、历史委托
已实现盈亏成交差价 × 数量 − 手续费 + 资金费用（有正负号）列表、弹窗「减仓后预估总已实现盈亏」= 当前已实现盈亏 + 本次减仓预估净盈亏
仓位价值开仓价值 = 面值 × 张数 × 开仓均价（中台列表「仓位价值」）；当前仓位价值 = 面值 × 张数 × 标记价格（弹窗「剩余持仓价值」、列表单位选 USDT 时的持仓量）列表、弹窗
仓位本金 / 仓位保证金全仓 = 张数 × 面值 × 开仓均价 / 杠杆；逐仓 = 逐仓保证金（逐仓余额）列表「仓位保证金」、收益率分母
收益率持仓收益率 = 未实现盈亏 / 仓位本金；平仓收益率（历史页）= 仓位已实现盈亏 / 仓位本金列表「回报率」、用户端持仓、历史仓位
减仓时逐仓保证金转出转出 = min（A，B，减仓前仓位保证金）
A = max【仓位保证金 × 减仓仓位价值 / 减仓前仓位价值 + 方向 × 减仓张数 × 面值 ×（平仓均价 − 开仓均价），0】
B = max【减仓前仓位保证金 + 方向 × 剩余张数 × 面值 ×（标记价格 − 开仓均价）− 剩余张数 × 面值 × 标记价格 / 杠杆，0】		逐仓 ADL 执行后的保证金与资金去向
预估强平价逐仓 =【逐仓余额 /（面值 × |张数|）− 方向 × 持仓均价】/（维持保证金率 + 爆仓手续费率 − 方向）
全仓（多仓位）=【（钱包余额 − Σ逐仓余额 + 其他仓位未实现盈亏）/（面值 × |张数|）− 方向 × 持仓均价】/（维持保证金率 + 爆仓手续费率 − 方向）
破产价格：同上，维持保证金率取 0；价格不存在时显示「--」		列表「强平价格」「破产价格」、用户端持仓
保证金率（逐仓）（逐仓余额 + 未实现盈亏）/（面值 × |张数| × 标记价格 ×（维持保证金率 + 爆仓手续费率））用户端持仓

由公式得出的两条结论：

  • 全仓：ADL 后钱包余额增加本次扣费后已实现盈亏，被减仓位的未实现盈亏按成交毛盈亏减少，扣除实际手续费后按最新钱包余额重算；同账户其他仓位强平价也可能因费用变化，不能承诺不变。
  • 逐仓：按「减仓时逐仓保证金」规则转出，B 项会把浮盈超出部分一并转出，使剩余仓位权益 = 剩余初始保证金。例：10x 逐仓 0.0108 BTC 被 ADL 0.01 BTC，逐仓保证金 89.11 → 2.34 U，预估强平价 74,678 → 80,039，收益率 71.79% → 202.83%。剩余仓位的强平价会靠近标记价格（与用户手动部分平仓的结果一致）。

维持保证金率、爆仓手续费率取各合约现有配置（原型示例值：0.5% / 0.06%）。

减仓后预估（每行显示「当前 → 减仓后」，如持仓 108 张 → 8 张；未输入时减仓后显示「--」）

五、API 相关调整

以下为建议的接口变动，字段名仅作示意，以研发定稿为准。

5.1 中台 · 当前持仓列表查询（调整）

  • 返回新增 adlLevel（1–5，取现有 ADL 指示灯计算结果，与用户端一致）。
  • 排序参数支持 unrealizedPnl / roe，方向 asc / desc。
  • 返回 contractSize（合约面值）与 qtyPrecision（张数精度，取合约现有配置），供列表显示换算，以及减仓张数精度校验与价值计算。
  • 返回 adlEnabled（是否可点）及 adlDisabledReason（LEVEL_NOT_5 / PNL_NOT_POSITIVE），服务端统一判断。

5.2 中台 · ADL 减仓执行（新增）

  • 入参：positionId、quantity（固定以「张」输入和提交；按合约数量精度校验，不进行币或 USDT 输入换算）。操作人从登录态获取。
  • 服务端校验（按顺序）：仓位存在 → 仓位 / 合约状态允许（P15）→ adlLevel == 5 且未实现盈亏 > 0（P14）→ quantity > 0 且符合精度 → quantity ≤ 当前持仓量。
  • 执行（同一事务）：撤销该仓位全部平仓类挂单（撤单原因 ADL_CANCEL）→ 以执行时标记价格生成系统平仓单并成交（来源 ADL，operator = 运营账号，手续费按实际收取）→ 释放保证金与已实现盈亏入交易账户 → 平台账户记录对应盈亏（无对手仓位）。
  • 返回：成交张数、成交价、适用费率、实收手续费、扣费后已实现盈亏、撤销挂单数量、是否全部平仓、剩余持仓量。
  • 错误码：QTY_EXCEEDS_POSITION、POSITION_NOT_FOUND、ADL_CONDITION_NOT_MET、POSITION_STATUS_NOT_ALLOWED、INVALID_QTY、SYSTEM_ERROR。
  • 幂等：前端提交时带请求 ID，防止重复提交导致重复减仓。

5.3 中台 · 订单 ID 明细（调整）

  • 订单明细展示删除操作人列。新增按持仓 ID 查询的操作日志接口，返回全体操作人员的时间、请求 ID、人员账号、张数、执行结果 / 原因、订单 ID、成交价与实收手续费，支持时间倒序分页；由服务端写入并鉴权，只读。请求 ID 幂等去重，失败也留痕，仓位全平后保留日志。

5.4 用户端 · 历史委托（调整）

  • 仅历史委托接口返回 ADL 记录与标签，并返回实际 fee / feeRate；其余历史接口不新增面向用户展示的 ADL 数据或标签。内部撮合、费用结算和审计数据完整保留。
  • 撤单原因新增 ADL_CANCEL，前端显示「已撤销 · 因 ADL」。
  • 历史仓位不新增 ADL 类型、记录或标签。
  • ADL 数量统一返回和展示张数；价值 = 张数 × contractSize × 执行价格。

5.5 平台账户对账（调整）

  • 用户侧资金流水不新增类型：ADL 与普通平仓一样不产生资金流水记录（R20）。
  • 平台账户流水新增类型「ADL 承接盈亏」，关联持仓 ID、订单 ID、操作人，供财务按日对账（R03：无对手仓位，多空持仓总量不再对等）。
